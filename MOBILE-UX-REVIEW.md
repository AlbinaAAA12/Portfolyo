# Мобильное портфолио: исследование и пересборка

Дата: 27 октября 2026. Объект: текущая production-сборка Portfolyo, затем её адаптация. Задача посетителя — познакомиться с дизайнером, выбрать работу, прочитать описание и посмотреть интерфейс, открыть подробный кейс или резюме.

## Источники и границы

- Свежие скриншоты и реальные переходы в браузере Codex: 390×844, дополнительная проверка 320×568. Десктоп 1280×832 зафиксирован как контроль сохранности дизайна.
- Исходный визуальный язык: существующие компоненты и токены сайта, ранее реализованные по Figma MCP. Новые изображения, палитра, тексты кейсов и видеоролики не создавались.
- Mobbin: доступные инструменты и поиск плагина не вернули подключение. Референсы из Mobbin не использовались; результаты поиска не выдумывались.
- [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html): контент должен оставаться доступным на узкой ширине, без необходимости прокручивать строки текста в двух направлениях. Одноколоночная компоновка — подходящий паттерн для чтения.
- [W3C: Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html): ориентир 44×44 CSS px для удобства нажатия. Это критерий уровня AAA, а не заявление о полном соответствии портфолио WCAG.

Это проверка интерфейса и сценариев, не пользовательское исследование с респондентами. Реальное устройство iOS/Android и экранный диктор в этой сессии не использовались. Медиа и содержание сохранены по запросу владельца, включая временные отзывы и отсутствие готового PDF.

## Принятая структура

На телефоне: шапка → профиль и приветствие → четыре кейса → горизонтальные отзывы → логотипы. В кейсе: выбор проекта → описание и теги → видео → возврат к кейсам / следующий проект. Переключатели «Инфа / Проекты» и «Описание / Макеты» удалены.

Адаптивная лента включается до 1100 px. На планшете карточки проектов размещаются в два столбца. Выше 1100 px сохранена прежняя композиция 1280×832 с масштабированием, без вертикальной прокрутки.

## План и реализация

1. Родительский агент: аудит реального интерфейса, выбор структуры, контракт адаптации и критерии проверки.
2. Luna high: локальная установка Visual Truth с отдельным DEV-модулем и воспроизводимым архивом зависимости для CI.
3. Luna high: разметка мобильной ленты, навигация, управление фокусом, состояния подсказок; существующий контент и desktop-коллаж сохранены.
4. Luna high: адаптивные стили, пропорции медиа, отзывов и модальных окон. Владение файлами разделено.
5. Родительский агент: браузерная проверка, конкретные исправления обнаруженных дефектов через исполнителей, повторная проверка и публикация.

## Критерии готовности

- Контент и медиа доступны без переключателей вида и без горизонтального переполнения страницы на 320 px.
- Все четыре кейса открываются; текущий пункт навигации виден; новый кейс начинается сверху.
- Возврат ведёт к списку работ; язык меняется без потери выбранного кейса; модалки возвращают фокус.
- Видео сохраняют пропорции, autoplay/muted/loop/playsInline, паузу вне видимой области.
- Отзывы прокручиваются отдельно, вертикальный скролл страницы над ними не перехватывается.
- Десктопные размеры, цвета, тексты, ассеты и композиция не изменены.
- Production не содержит редактор Visual Truth; локальный редактор доступен в DEV.
- Сборка, проверка зависимостей и браузерная проверка пройдены; итог в `design-qa.md`.
